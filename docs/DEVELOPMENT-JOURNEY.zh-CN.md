# BetterJoy Direct：开发历程

[English](DEVELOPMENT-JOURNEY.md) | [简体中文](DEVELOPMENT-JOURNEY.zh-CN.md)

本文记录从 BetterJoy 上游快照到 BetterJoy Direct 的工程过程，重点保留观察、错误假设、修正、证据和最终决策。

## 起点

项目从 Davidobot/BetterJoy 提交 `b6715638a3ed1084f8968e8cafebbc6fe2ed0096` 开始。实际目标很明确：通过蓝牙或 USB 连接 Switch Pro Controller，在不依赖 Steam 的情况下，为 Windows 提供可靠的系统级 Xbox 360/XInput 手柄。

原项目已经具备正确的核心链路：

```text
Switch HID → BetterJoy 解析 → ViGEmBus → 虚拟 Xbox 360 手柄
```

若替换成全新驱动，范围会扩展到内核开发、签名、分发和长期兼容维护。BetterJoy Direct 因此保留 ViGEm 链路，把精力集中在应用层的正确性、恢复能力和可用性上。

## 第一阶段：建立输入边界

最先要解决的风险不是按键映射，而是哪些 HID 数据包有资格成为手柄输入。

上游读取路径可能让命令响应、短包、重复时间戳或错误 report ID 进入输入处理。首次连接和重连时，用于唤醒手柄的 Home 或 Capture 也可能被误认为新的用户操作。

Direct 路径新增 `InputReportGuard`：

- 只接受预期的 `0x30` 输入布局和精确长度；
- 拒绝命令响应、短包及其它 report ID；
- 拒绝重复时间戳，同时允许单字节时间戳回绕；
- 等待全部按键释放和约 300 毫秒稳定输入后才放行输出；
- 输入门未开启时清空按键和摇杆状态。

回归测试会检查全部 256 种单字节 report ID，而不只测试几个典型值。

## 第二阶段：重连时不遗留状态

原来的 HID 句柄、采集线程和虚拟手柄对象存在生命周期交叉。读取线程仍运行时关闭句柄可能产生间歇故障；重复扫描还可能给界面按钮重复注册事件。

新的生命周期会先停止采集并等待读取线程结束，再释放 HID 和虚拟输出对象。手柄初始化失败会记录明确原因，并把设备交还给后续扫描。扫描定时器触发的界面更新也会切回 Windows Forms UI 线程。

程序还明确增加了输入超时边界：超过 1.5 秒没有有效报文时，先把虚拟输入归零，再把设备视为断开。

## 第三阶段：全零报文仍有旧轴值

实体测试出现了一个最初看似不可能的结果：BetterJoy 已提交全零虚拟报文，但 Windows XInput 仍显示上一个设备状态留下的非零轴值。

独立的原生探针脱离 HID 解析后复现了同一现象，从而把应用输入问题与虚拟设备初始化问题区分开来。

最终方案是等待 XInput 槽位可读，提交一个低于标准 XInput 死区的最小轴变化，然后立即提交中立报文。虚拟输出测试会重复创建、移动、归零和断开流程，防止该行为回归。

## 第四阶段：让运行状态可见

当界面不说明程序正在做什么时，即使重连正确也很难让人信任。旧布局因此被现代双语 Windows Forms 界面替换，包含：

- 四个手柄卡片和本地化断开状态；
- Windows 蓝牙设置和游戏控制器测试入口；
- 展示驱动、枚举、初始化和快捷键事件的连接日志；
- 保存到配置的中英文切换；
- 立即生效的 Steam 快捷键和陀螺仪控制；
- 可滚动的高级配置面板。

原来的全强度、300 毫秒定位震动体感过强，因此改为强度 `0.18`、时长 `120 ms` 的短脉冲，同时限制异常配置并阻止连续点击叠加震动。

## 第五阶段：窗口和托盘修正

第一版现代窗口信息更清楚，但尺寸太大，实际几乎不能缩小。只缩小窗口尺寸后，手柄卡片又被压扁，内部构图发生变化。

最终修正把外部尺寸与内部比例分开处理。默认客户区设为 `900×700`，最小尺寸约为 `760×620`，主要行高按照原 `980×820` 界面缩放。标题、状态、手柄卡片、操作栏、快捷控件和底栏之间的相对比例得以保留，同时提供有效缩放范围。

另一个托盘问题来自错误的显示顺序：窗体仍处于最小化状态时就被显示，之后才恢复正常状态。现在会先准备正常窗口状态和任务栏可见性，再显示窗体，从而减少空白帧和重复布局。

## 第六阶段：先理解桌面输入，再做简化

最后一次主要设计变化来自一个容易误判的现象：陀螺仪鼠标可以移动光标，但摇杆和普通按键在 Windows 桌面看起来没有作用。

这个行为其实正确。陀螺仪鼠标产生鼠标事件，普通控制则保持 XInput。Windows 资源管理器不会把 XInput 当作桌面导航协议，所以这些按键应当在 `joy.cpl`、手柄测试或游戏中生效，而不是在桌面生效。

“自定义键鼠绑定”并不会把整个手柄转换为桌面输入。它只控制少量旧特殊按键映射和全局键鼠监听。控件名称暗示了更大的能力，反而让正确的 XInput 行为看起来像故障。

最终选择删除该功能：

- 删除现代界面的开关和映射入口；
- 删除 `EnableDesktopInput`；
- 删除手柄路径中的旧键盘/鼠标事件发射；
- 删除启动路径和旧重映射窗体中的全局键鼠捕获；
- 让陀螺仪鼠标成为独立运行时模式；
- 保留单独控制的固定 Steam 快捷键；
- 在内部继续兼容旧 `joy_` 手柄到手柄重映射。

这次变化首先修正了我们对功能边界的理解，其次才是界面清理。

## 验证证据

发布版本从多个层次进行了检查：

- **343 项输入回归：**报文边界、全部 256 个 report ID、时间戳重复与回绕、重连释放门、校准失败、死区、快捷键按下沿、陀螺仪方向、Guide 抑制及旧键鼠监听删除。
- **32 组双语文案与功能检查：**中英文、运行时控件、窗口尺寸和托盘恢复顺序。
- **虚拟 Xbox 生命周期：**连续三轮创建、移动、归零和断开。
- **实体蓝牙测试：**704 个 XInput 样本、一次物理断开、成功自动重连、最终轴归零且没有输出错误。
- **界面渲染检查：**实际打开中英文 `900×700` 预览，检查缺失控件、裁切和异常换行。
- **便携包验证：**生成 ZIP 后重新读取必需文件和依赖声明并核对哈希。

## 仍然存在的不确定性

现有证据支持已测试的 Switch Pro 蓝牙和 Windows XInput 链路，但不能证明所有手柄型号、USB 芯片、游戏、反作弊、Steam 配置和远程控制产品。

ViGEmBus 上游也已经停止维护。BetterJoy Direct 可以改善应用层的使用边界，但不能替代该内核驱动的维护和签名工作。

## 保留下来的经验

1. 修改映射前先验证输入边界。
2. 把线程、HID 句柄和虚拟设备生命周期视为同一个关闭序列。
3. 通过 Windows XInput 验证输出，不能只检查托管对象状态。
4. 诊断输入时要区分 Windows 桌面行为和游戏手柄行为。
5. 改变窗体外部尺寸时保留内部布局比例。
6. 当控件名称无法诚实表达心智模型时，应直接简化功能。
7. 二进制和原始诊断记录适合作为 Release 证据或本地产物；源码历史应保持可审阅。
